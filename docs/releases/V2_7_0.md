# v2.7.0 - Cross-Repository Evidence and Conservative Forecast Closeout

Release date: 2026-07-28

## Overview

v2.7.0 closes the post-v2.4 development scope as one additive public release.
It combines three related capabilities:

- versioned compatibility and retrieval-reproducibility evidence for tracked
  Materials and Battery artifacts;
- leakage-safe Battery forecast benchmarking with the negative result preserved;
- checksum-bound cross-repository process-characterization handoff and a
  representative NIST AM-Bench workflow that stops before unsupported modeling.

This release is primarily about defensible evidence flow and claim control. It
is not presented as a predictive-model success or an autonomous engineering
system.

## Included Development Stages

The earlier labels `v2.5.1`, `v2.5.2`, `v2.6.1`, and `v2.6.2` were internal
feature-stage identifiers under `Unreleased`. They are consolidated into the
public semantic release `v2.7.0`; they are not separate public releases.

## Compatibility and Retrieval Evidence

v2.7.0 adds explicit, version-allowlisted adapters for the tracked Materials
v2.2.4 structure summary and Battery v2.3.5 source-lineage summary.

The implementation provides:

- deterministic raw-byte checksum replay;
- canonical logical JSON checksum replay;
- strict preservation of unresolved fields;
- compact compatibility summaries;
- preview, run, and validate CLI commands;
- separation of byte identity, logical-content agreement, metadata agreement,
  and scientific validity.

The recorded outcomes are deliberately limited:

- Materials compatibility: compatible with restrictions;
- Battery compatibility: partial;
- retrieval reproducibility: `insufficient_evidence` for both tracked domains
  because no independent second retrieval event is available.

No network retrieval, source mutation, migration, credential use, or model
execution is required for these audits. Same-file and cross-domain comparisons
remain prohibited.

## Battery Forecast Benchmark

v2.7.0 includes a leakage-safe five-cycle capacity-retention forecast benchmark
using:

- battery-disjoint GroupKFold validation;
- train-only preprocessing;
- a persistence baseline;
- a fixed Ridge baseline;
- deterministic prediction and diagnostic checksums;
- preview, run, and validate CLI commands.

The actual result is **Unsupported** as a predictive improvement claim:

- Ridge pooled MAE: `4.1537`;
- persistence pooled MAE: `3.4256`;
- Ridge improves on 13 of 33 evaluated batteries.

The deterministic failure diagnostics preserve this result. Influence,
leave-one-battery-out, trajectory-quality, fixed-cycle regime, local-trend,
physical-plausibility, and metadata-comparability audits do not identify a
single exclusion that reverses persistence superiority. Source and test-condition
comparability also remains unestablished.

No feature retuning, clipping, target redefinition, battery exclusion, or model
selection was used to manufacture a positive result. The release makes no
zero-shot, SOH, RUL, degradation-mechanism, lifetime, or engineering claim.

## Cross-Repository Characterization Handoff

The data repository now consumes schema `1.0` characterization bundles from the
independently installable `materials-characterization-analyzer` repository.

The handoff validates:

- explicit `sample_id` identity rather than row order;
- bundle paths, sizes, hashes, and exact long-format feature columns;
- finite numeric values and unit-labeled semantic feature identity;
- source and preprocessing provenance;
- sample-context and external process-table identity fields;
- one-to-one process-characterization integration;
- deterministic reports and manifests.

Tracked public workflows cover:

- DWCNT multi-technique evidence;
- the RWGS XRD/EDS case while preserving the blocked SEM quantitative result
  and unresolved Ni context;
- four carbon material classes without treating material-class differences as
  controlled process effects;
- NIST AM-Bench 2018-02 optical-metrology features joined to consumer-owned
  process conditions.

These workflows validate the software contract and provenance chain. They do
not prove phase identity, chemical state, identical aliquots, mechanism,
causality, prediction, optimization, or engineering-release suitability.

## Representative NIST AM-Bench Workflow

A one-command representative workflow now performs:

```text
verified NIST source-table case
-> sample-ID and provenance integration
-> artifact integrity closeout
-> process-design identifiability audit
-> bounded minimum next-experiment plan
-> Diagnostic scientific closeout
```

The current evidence contains:

- one material: IN625;
- one system: NIST AMMT;
- 10 explicit laser-track samples;
- three coupled power-speed conditions;
- source-reported optical-microscopy melt-pool width and depth metrics;
- 50% coverage of the observed 2 x 3 power-speed grid.

The workflow correctly returns
`not_ready_for_predictive_or_causal_modeling`. The immediate bounded
recommendation is to add the three missing factorial combinations with at least
three traces per condition. Midpoint-power and validation stages remain
conditional on machine, calibration, safety, and experimental-purpose review.

No response model is trained and no process optimum is generated.

## Preserved Scientific Outcomes

The release intentionally preserves the following non-positive or restricted
results:

- Materials composition physics: `performance_degraded`;
- known-structure predictive value: `structure_predictive_value_limited`;
- representative Materials model: none;
- Materials compatibility: compatible with restrictions;
- Battery compatibility: partial;
- retrieval reproducibility: `insufficient_evidence`;
- Battery Ridge forecast improvement: `unsupported`;
- public process-characterization cases: `Diagnostic`;
- NIST predictive or causal readiness: blocked.

A passing release test does not upgrade any of these outcomes.

## Compatibility

v2.7.0 is additive and preserves existing valid CLI commands, loaders, public
output schemas, tracked source tables, and local-only artifact policies. The two
materials repositories remain independently installable and communicate through
versioned files rather than internal imports.

## Security and Artifact Policy

The release does not intentionally include:

- credentials or credential values;
- private or proprietary datasets;
- raw downloaded archives not approved for redistribution;
- generated `outputs/` directories;
- local absolute paths;
- arbitrary serialized Python objects;
- row-level model predictions intended only for local analysis.

External datasets, publications, and software retain their own licenses and
citation requirements. The repository MIT license does not relicense them.

## Validation Boundary

Release validation covers software behavior, deterministic artifacts, metadata
consistency, and tracked cross-repository compatibility evidence. It does not
establish instrument calibration, measurement uncertainty, sample
comparability, causal validity, mechanism validity, predictive generalization,
or production engineering readiness.

## Explicit Nonclaims

v2.7.0 does not claim:

- successful Battery forecasting;
- SOH or RUL prediction;
- degradation-mechanism identification;
- automatic phase or chemical-state identification;
- causal laser-power or scan-speed effects;
- process optimization;
- cross-machine or cross-material generalization;
- autonomous scientific or engineering decisions;
- production deployment readiness.
