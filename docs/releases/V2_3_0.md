# v2.3.0 - PGIR Governance and Battery Trajectory Evidence

## Overview

v2.3.0 adds a Physically Grounded Intermediate Representation (PGIR)
governance layer and closes a bounded Battery trajectory evidence workflow.
The release is representation- and evidence-first: it does not introduce a
physics solver, degradation model, predictor, or production decision system.

The five milestones are:

- v2.3.1: PGIR concepts, representation maturity, schema ownership, operator
  taxonomy, capability stages, and accepted architecture RFCs.
- v2.3.2: conformance gates and a Battery Observation / bounded operational
  State / Trajectory adapter pilot.
- v2.3.3: mechanism-candidate data sufficiency, protocol comparability,
  evidence-gap, and identifiability audits.
- v2.3.4: deterministic execution of one selected descriptive
  capacity-trajectory Evaluator.
- v2.3.5: immediate-source lineage, source-supported metadata recovery, and
  predeclared evaluator policy-stability auditing.

## PGIR Architecture

PGIR records conceptual roles for observations, states, trajectories,
relations, operators, uncertainty, and provenance. Existing v2.2 schemas and
artifacts remain authoritative; v2.3 adds governance and conformance metadata
without migrating or renaming them.

`Evaluator`, `Transformer`, and `Propagator` remain distinct. The Battery work
executes one bounded `Evaluator`; it does not execute a `Propagator`, solve an
ODE/PDE, or fit a mechanism parameter.

## Representation and Conformance

Cycle summaries remain observations. A registered adapter creates bounded
operational State summaries and ordered Trajectory metadata only where the
source evidence and conformance gates support that representation. The
workflow does not infer a latent electrochemical state.

Row-level Observation, State, and Trajectory records remain local-only. The
repository tracks compact, identity-free coverage, maturity, transition,
readiness, and decision artifacts.

## Identifiability Decision

The available evidence does not identify the audited Arrhenius, diffusion, or
resistance mechanisms. Missing or insufficient evidence includes controlled
condition comparability, mechanism-specific internal state and geometry,
cycle-specific commanded protocol for variable-condition groups, and source
measurement/calibration uncertainty.

The v2.3.3 decision is `descriptive_evaluator_only`. One capacity-trajectory
consistency Evaluator is selected for bounded descriptive execution; no
representative degradation mechanism is selected.

## Evaluator Execution

v2.3.4 evaluates 33 of 34 trajectories. One four-observation trajectory is
blocked by the predeclared minimum-five-observation rule. The evaluator uses
fixed gap-aware rules for descriptive candidates such as missing-cycle gaps,
non-monotonic changes, abrupt changes, plateaus, changing fade slopes,
variability, and terminal retention.

The result is `descriptive_evaluator_executed_with_restrictions`. Thresholds
are deterministic algorithm settings, not measurement uncertainty, physical
transition boundaries, or optimized predictive thresholds.

## Metadata Recovery

v2.3.5 recovers only metadata explicitly supported by the existing local
source:

- cycle start timestamp: 2,495 / 2,495 rows
- ambient temperature: 2,495 / 2,495 rows
- discharge duration: 2,495 / 2,495 rows
- measured temperature/current/voltage summaries: 2,495 / 2,495 rows
- group-level protocol documents: 34 / 34 cells
- impedance rows: 1,956, including 1,947 complete Re/Rct pairs

No default values are filled. Timestamp timezone, per-measurement uncertainty,
official original NASA snapshot/version, and cycle-specific commanded protocol
logs for variable-condition groups remain unavailable.

## Policy Stability

Nine threshold, reference, window, and gap configurations are declared before
the stability audit. Finding counts range from 272 to 508 across policies; the
v2.3.4 baseline contains 383 findings. Overlapping findings are consolidated
into 489 bounded descriptive events:

| Stability class | Events |
| --- | ---: |
| `stable_across_policies` | 211 |
| `stable_with_restrictions` | 97 |
| `policy_sensitive` | 50 |
| `insufficient_support` | 131 |

The closeout decision is
`descriptive_evaluator_stable_with_policy_restrictions`. Stability does not
turn a descriptive event into a degradation mechanism.

## External Data Decision

The release records
`selective_external_source_documentation_required` only for evidence genuinely
unavailable from the local source. NASA PCoE is the preferred route for
official protocol, source-version, calibration, and uncertainty documentation.
NIST OAR is a discovery/catalog route. CALCE would require a separate
comparability audit before any combination. NREL and NVD credentials are not
substitutes for Battery scientific metadata. No external data is downloaded.

## Compatibility and Artifact Policy

v2.3 is additive. Existing v2.2 scientific decisions, schemas, case-study
scripts, output paths, and CLI behavior are preserved. Scientific schema
versions remain independent of the public release version.

Raw source files, cell/cycle lineage, row-level trajectories, per-policy
findings, consolidated event rows, reports, and plots remain under ignored
local paths. Tracked outputs are compact and contain no cell identifiers, raw
series, credentials, or absolute host paths. No raw dataset is redistributed
with the release.

## Explicit Nonclaims

v2.3.0 does not claim:

- a degradation mechanism was identified
- Arrhenius behavior, diffusion, or resistance growth was fitted
- a physical parameter or uncertainty interval was estimated
- SOH, RUL, lifetime, or failure was predicted
- a policy-stable event is a physical transition
- cross-dataset or production generalization
- maintenance, charging, safety, or other production decisions
- a general physics intelligence, GNN/PINN, or autonomous experiment system

## Future Requirements

Mechanism work would require stronger source evidence before additional
fitting or tuning: official source-version documentation, cycle-specific
commanded protocol, physical-time and condition comparability, measurement and
calibration uncertainty, and a separate cross-dataset comparability audit.
A second-domain PGIR reuse audit is also deferred beyond v2.3.0.
