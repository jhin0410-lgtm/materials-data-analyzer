# v2.4.0 - External Source Governance and Bounded Physical Execution

## Overview

v2.4.0 adds two completed, bounded platform capabilities:

- versioned external-source metadata and provenance contracts with actual
  Battery and Materials mappings
- the first executable PGIR physical Model Contract, demonstrated on a
  synthetic one-dimensional scalar diffusion benchmark

The release preserves the v2.2 Materials conclusions and the v2.3 Battery
evidence boundaries. It does not introduce a general PDE framework, a Battery
diffusion mechanism, a real-material parameter estimate, or a production
simulation system.

## Release Scope

The release contains two internal feature stages:

- v2.4.1: external-source contracts and restricted second-domain PGIR
  representation reuse
- v2.4.2: bounded PGIR Model Contract and analytical/numerical diffusion
  benchmark

The public semantic version is v2.4.0. Scientific schema versions remain
independent of the public product version.

## External-Source Contract

v2.4.1 separates the following concepts into versioned JSON-safe contracts:

- external source system
- logical dataset
- dataset snapshot
- distribution artifact
- retrieval event
- source documentation
- local derived artifact
- provenance assessment

This separation prevents a service, dataset, snapshot, downloaded archive,
retrieval timestamp, and local processed result from being treated as the same
object.

Credential values, authorization headers, signed secrets, live response
objects, and user-specific absolute paths are prohibited from persisted
records. Authentication metadata may contain only approved environment-variable
names.

## Source and Provenance Boundaries

### Materials Project

The existing bounded Materials Project acquisition is represented as an
authoritative API source with local derived structure evidence. The release
preserves the bounded existing-ID scope and does not execute a new API
retrieval.

The named dataset snapshot, exact API client version, and some terms or
documentation evidence remain unresolved. Authoritative source status does not
mean that every derived result is independently or experimentally validated.

### NASA-Derived Battery Archive

The existing 34-cell Battery package is represented as a verified immediate
upstream archive. The local ZIP checksum and metadata checksum remain
preserved.

The official original NASA snapshot/version, original retrieval timestamp,
license evidence, cycle-specific commanded protocol for variable-condition
groups, and measurement/calibration uncertainty remain unresolved.

The release does not promote the immediate upstream archive into a verified
official NASA snapshot.

## PGIR Model Contract

v2.4.2 adds the first strict executable PGIR Model Contract for this bounded
synthetic problem:

```text
dc/dt = D d2c/dx2
x in [0, L]

c(0, t) = 0
c(L, t) = 0
c(x, 0) = A sin(pi x / L)
```

The canonical benchmark uses:

- domain length: `L = 1 m`
- diffusivity: `D = 0.1 m^2/s`
- amplitude: `A = 1`
- final time: `T = 0.4 s`
- 21 spatial points
- 40 time steps
- `dx = 0.05 m`
- `dt = 0.01 s`
- FTCS ratio: `D*dt/dx^2 = 0.4`

The values are synthetic benchmark parameters. They are not properties of a
Battery, electrode, semiconductor, or other real material.

## Propagators and Numerical Gate

The release registers and executes:

- one exact analytical Propagator using the single sine eigenmode solution
- one deterministic explicit FTCS numerical Propagator
- one analytical-numerical benchmark Evaluator

The FTCS stability requirement is:

```text
0 < D*dt/dx^2 <= 0.5
```

An unstable requested configuration is blocked. The implementation does not
silently alter `D`, `dt`, `dx`, or the requested grid.

The benchmark enforces:

- dimensional compatibility
- finite and positive physical parameters
- spatial and temporal domain validity
- initial-condition and boundary-condition compatibility
- numerical-backend eligibility
- finite-result and nonnegative-field checks
- deterministic artifact checksums

## Artifact and Security Policy

Field arrays, grid-level values, detailed residuals, generated reports, and
plots remain in ignored local output directories.

Tracked release artifacts are compact summaries and schemas. They contain no:

- raw field arrays
- Battery cell identifiers
- Materials row-level identifiers
- API response bodies
- credentials
- signed URLs
- local absolute paths
- arbitrary serialized Python objects

The implementation does not use network access, dynamic imports, `eval`,
`exec`, pickle, parameter fitting, model training, GNN, PINN, or DFT
calculation.

## Compatibility

v2.4.0 is additive.

The release preserves:

- v2.2 Materials artifacts and negative or limited predictive conclusions
- v2.3 Battery provenance, evaluator, identifiability, stability, and
  external-data decisions
- existing scientific schema versions
- existing public CLI and valid workflows
- local-only raw and row-level artifact policies

No released payload is bulk-migrated and no previous release tag is modified.
