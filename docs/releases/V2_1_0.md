# v2.1.0 - Scientific Registry and Physics-Consistency Trust Layer

## Overview

v2.1.0 adds a persistent local registry and bounded scientific execution layer
to the v2 platform scaffold. The release focuses on provenance, lineage,
diagnostics, scientific metadata, unit-aware consistency checks, and explicit
claim boundaries.

This is not a physics-aware ML release. It does not generate predictive
physics features, train models, run DFT/FEM/CFD, identify phases, or make
production scientific decisions.

## Persistent Run and Artifact Registry

- Local-only SQLite registry under `outputs/platform_registry/`.
- Run and report manifest ingestion.
- Artifact instance records and input/output lineage.
- Reproducibility status, run comparison, deterministic export, and schema
  migration coverage through registry schema version 4.
- Metadata-only storage: no raw rows, credentials, model binaries, or host
  absolute paths.

## Reproducibility and Lineage

The registry records config, code, input, and output checksums when available.
It distinguishes static artifact definitions from run-specific artifact
instances and keeps registry exports deterministic.

## Policy Diagnostics and Evidence Gaps

v2.1 adds deterministic diagnostics over persisted registry metadata:

- validation-policy and trust-policy compatibility checks
- evidence-gap records
- registered claim evaluation
- evidence-graph summaries
- optional report summaries from stored diagnostics only

Diagnostics do not rerun scripts, recompute metrics, read raw data, train
models, or interpret free-form claims.

## Scientific Constraint Registry

The scientific registry adds metadata for unit-aware consistency checks:

- constraint IDs and evaluator IDs
- required variables and units
- assumptions, validity conditions, and tolerances
- knowledge-pack references
- equation displays that are never executed

Initial domain knowledge packs cover materials, battery degradation,
manufacturing process, reliability degradation, and XRD crystallography.

## Unit and Applicability Model

The unit registry supports bounded compatible conversions such as Celsius to
Kelvin, percent to fraction, degrees to radians, nm to angstrom, and MPa to
GPa. Missing or unsupported units are treated as metadata limitations rather
than automatic scientific violations.

## Bounded Scientific Execution

v2.1 can execute registered pure evaluators for scalar or small-list metadata
checks. It validates request structure, applicability, variables, units,
assumptions, and tolerance boundaries before producing findings.

Execution remains bounded and local:

- no arbitrary equation parsing
- no arbitrary callable or import execution
- no network calls
- no raw dataset scans
- no model fitting
- no global state mutation

## XRD Bragg and Scherrer Support

Bragg support is limited to supplied wavelength/order/two-theta consistency and
bounded d-spacing estimation. It does not identify phases, index peaks,
confirm crystal structures, or infer composition.

Scherrer support is limited to bounded crystallite-size estimates under
supplied assumptions. It does not prove particle size, grain size, morphology,
phase purity, or material identity.

## Scientific Trust Boundary

v2.1.5 adds scientific trust evaluation over stored execution evidence:

- evidence levels from `metadata_registered` through
  `bounded_quantity_estimated`
- constraint-role classification
- model-constraint and feature-candidate eligibility boundaries
- supported, unsupported, and prohibited scientific claim decisions
- schema v4 persistence for trust evaluations, feature eligibility, and claim
  boundaries

The release does not grant `independently_validated` or
`production_validated` status from execution alone.

## Feature Candidate Registry

The feature candidate registry stores deterministic metadata for possible
future physics-aware features, including required variables/units,
availability policy, leakage risk, assumptions, and claim boundaries.

Initial candidates include:

- materials composition descriptors
- battery retention/efficiency/resistance candidates
- XRD d-spacing and crystallite-size candidates
- manufacturing process-window and mass-balance candidates
- reliability exposure and degradation-slope candidates

These are metadata-only candidates. v2.1 does not calculate feature values,
write feature datasets, feed features into models, or claim predictive value.

## Report Integration

Platform reports can optionally summarize stored registry diagnostics and
stored scientific trust rows. Report generation is read-only and does not run
scientific execution, recompute trust evaluations, read raw data, generate
features, or train models.

## CLI Additions

New and expanded CLI surfaces include:

- registry initialization, ingestion, comparison, diagnostics, and export
- scientific constraint and knowledge-pack inspection
- unit conversion
- scientific input validation
- preview and execute bounded scientific checks
- persisted finding and claim inspection
- scientific trust evaluation
- scientific feature candidate inspection and eligibility checks
- scientific trust export and validation
- opt-in report summaries for diagnostics and scientific trust

## Security Boundaries

v2.1 keeps the platform additive and constrained:

- no `eval` or `exec`
- no arbitrary equation execution
- no arbitrary user-supplied import paths
- no subprocess or shell execution from configs
- no network operations
- no raw dataset reads
- no model training
- SQL operations are parameterized
- local outputs remain ignored under `outputs/`

## Backward Compatibility

Existing v1.x case-study scripts, output schemas, processed compact artifacts,
and public CLI analyzer workflows remain unchanged. v2.1 adds registry and
scientific metadata layers without replacing the older scripts.

## Known Limitations

- No physics-aware ML model is trained.
- No generated scientific feature table is produced.
- No feature candidate is validated as predictive.
- No DFT, FEM, CFD, PINN, GNN, SHAP, or phase identification is performed.
- No production scientific decision or calibrated operational claim is made.
- Registry databases, scientific execution outputs, exports, and reports are
  local-only and are not release assets.
