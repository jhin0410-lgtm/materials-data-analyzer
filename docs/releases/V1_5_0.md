# v1.5.0 - Reliability Validation and Trust Boundary

## Overview

v1.5.0 adds a complete reliability/risk case study using Backblaze Hard Drive
Test Data 2013. The release focuses on data contracts, source provenance,
full-year normalization, event/censoring integrity, leakage-aware validation,
fixed baseline classification, and conservative trust-boundary closeout.

This is a retrospective offline validation and diagnostic-ranking case study.
It is not a production drive-failure alerting system.

## Reliability Task

The selected v1.5 task is 7-day binary failure-risk classification:

- Prediction origin: asset observation date
- Horizon: failure within the next 1 to 7 days
- Lookback: previous 7 calendar days including the prediction-origin day
- Eligible prediction origins: 4,892,482
- Positive rows: 4,797
- Positive assets: 706
- Row prevalence: 0.000980484
- Positive asset prevalence: 0.0242845

Same-day failure rows, post-failure rows, and right-edge rows without full
7-day future visibility are excluded from prediction origins.

## Validation Hierarchy

Primary evidence:

- asset-disjoint validation
- time-aware validation
- combined asset/time validation

Secondary reference:

- stratified random row split as an optimistic reference only

The release explicitly distinguishes known-asset future prediction,
unseen-asset generalization, and combined unseen/future validation. Random row
split is not used as primary evidence because repeated daily origins and
same-asset dependence can inflate results.

## Baseline Models

Fixed classical baselines only:

- Dummy prior classifier
- Logistic regression
- Random forest
- Histogram gradient boosting

There is no hyperparameter search, SMOTE, SHAP, survival model, RUL regression,
Weibull fitting, or causal maintenance analysis.

## Key Metrics

- Best primary median PR-AUC: 0.0998
- Best combined asset/time PR-AUC: 0.1119
- Reference combined top 1% precision: 0.0703
- Reference combined top 1% lift: 62.9x
- Reference combined top 1% failed-asset capture: 0.846

The top-risk result is evidence of retrospective ranking concentration. It is
not 84.6% prediction accuracy, not a 7% calibrated failure probability, and
not a production alert threshold. The combined top 1% still has about 92.97%
row-level non-positive burden and repeated-origin alert dependence.

## Trust Boundary

v1.5.5 closes the case study with stricter model eligibility:

- v1.5.4 input statuses: `candidate_for_further_validation=12`,
  `diagnostic_only=4`
- v1.5.5 trust eligibility: `descriptive_only=4`, `diagnostic_only=12`
- representative model: `none_selected`
- SHAP: `deferred_not_justified`
- survival/RUL: `deferred_not_ready`
- release readiness: `release_ready` as a bounded offline trust-boundary
  demonstration

No model is promoted to production or representative status.

## Known Limitations

- Backblaze 2013 alone does not establish cross-year, cross-company, or
  cross-fleet generalization.
- Non-failure drive exits have uncertain operational meaning.
- Repeated daily prediction origins are not independent samples.
- Non-dummy models use deterministic resource-limited training subsampling.
- Scores are uncalibrated relative risk-ranking scores.
- No maintenance action, replacement reason, confirmed failure mode, or
  prospective deployment evidence is available.

## Future Work

Stronger reliability claims would require:

- multiple years and external holdout periods
- independent data-center or fleet validation
- drive retirement and replacement reasons
- maintenance/intervention logs
- confirmed failure modes
- consistent SMART semantics across drive models
- independent calibration periods
- cost information for inspection and false alerts

The next platform phase should focus on reusable pipeline configuration,
artifact registries, validation registries, and trust-policy registries rather
than tuning the current Backblaze baselines.
