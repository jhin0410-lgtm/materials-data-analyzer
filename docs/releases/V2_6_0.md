# v2.6.0 - Evidence-Line Closeout and Cross-Repository Integration

Release date: 2026-07-28

## Overview

v2.6.0 closes the completed post-v2.4 work as one additive stable release. It
includes the internal v2.5 compatibility and retrieval-reproducibility stages,
the full checksum-bound Battery v2.6.1-v2.6.14 external-evidence line, and the
reviewed cross-repository process-characterization integration work.

A separate v2.5.0 release was not created. v2.5.1 and v2.5.2 were completed
feature stages, but no public v2.5 boundary existed before the v2.6 evidence
line was implemented and closed. v2.6.0 is therefore the smallest truthful
stable version for the integrated repository state.

This release is primarily a software, provenance, and scientific-claim closeout.
It is not presented as a predictive-model success or an autonomous engineering
system.

## v2.5 compatibility and retrieval evidence

v2.5.1 provides explicit, version-allowlisted adapters for the tracked Materials
v2.2.4 structure summary and Battery v2.3.5 source-lineage summary. It performs
deterministic raw-byte and canonical logical JSON checksum replay while
preserving unresolved fields.

Recorded outcomes:

- software compatibility verdict: **Supported**;
- Materials adapter: `compatible_with_restrictions`;
- Battery adapter: `partial`;
- provenance portability: **Diagnostic**.

v2.5.2 separates exact-byte agreement, canonical logical-content agreement,
metadata agreement, and scientific validity. Both tracked retrieval cases remain

exists. Same-file and cross-domain comparisons remain prohibited.

No network retrieval, credential access, source mutation, migration, or model
execution is required for these audits.

## Battery v2.6 benchmark and evidence line

### Registered warm-start benchmark

v2.6.1 evaluates a five-cycle capacity-retention forecast using battery-disjoint
GroupKFold validation, train-only preprocessing, a persistence baseline, and a
fixed Ridge baseline.

The actual result is **Unsupported** as a Ridge generalization improvement:

- Ridge pooled MAE: `4.1537`;
- persistence pooled MAE: `3.4256`;
- Ridge improves on 13 of 33 evaluated batteries.

The scenario is warm-start cross-battery forecasting. It is not zero-shot and
does not support SOH, RUL, lifetime, mechanism, calibrated probability, or
engineering-decision claims.

### Failure diagnostics and comparability

v2.6.2 preserves the benchmark and adds deterministic failure diagnostics. The
top five batteries concentrate Ridge excess error, but no leave-one-battery-out
exclusion reverses persistence superiority. The diagnostics do not justify
retuning, clipping, target redefinition, or battery exclusion.

v2.6.3 records `comparability_not_established`. Chemistry, nominal capacity,
cycle-specific commanded protocols, cutoff policy, calibration/uncertainty, and
the official NASA snapshot remain unresolved or heterogeneous.

### External-cohort gate and SNL evidence

v2.6.4 records:

- inventory review: `admitted_with_restrictions`;
- cross-cohort comparability: `not_admitted`;
- predictive validation: `blocked`;
- overall: `not_admitted_for_cross_cohort_validation`.

v2.6.5-v2.6.10 then perform progressively bounded SNL LFP evidence work:
source-document recovery, ZIP identity and safe-entry inventory, repository
nomenclature binding, six-file schema observation, 24-row cycle-regime review,

These stages establish useful document, archive, schema, and candidate-regime
evidence, but they do not establish exact physical-cell identity, cycle-command
to row binding, instrument-channel semantics, an official versioned
provider snapshot, cross-cohort comparability, or predictive-validation
eligibility.

### Michigan source path and final closeout

v2.6.11 selects Michigan Formation for source binding only, not cohort admission.
v2.6.12 recovers provider-package structure but not an exact file manifest or
provider-to-local binding. v2.6.13 records the observed provider metadata-access
HTTP 403 without converting that observation into a claim of global provider
unavailability.

v2.6.14 verifies all 13 tracked v2.6 stage artifacts and closes the evidence
line. Final decisions are:

- evidence-line integrity: `verified`;
- registered NASA warm-start benchmark: `preserved`;
- Ridge generalization: `unsupported`;
- cross-cohort comparability: `not_established`;
- external-cohort admission: `not_admitted`;
- predictive-validation readiness: `not_ready`;
- provider-to-local binding: `not_established`;
- engineering-decision readiness: `not_ready`;
- scientific closeout: **Inconclusive**.

The strongest evidence is the complete checksum-bound chain. The primary
limitation is missing source-backed compatible conditions and provider-to-local
binding, not insufficient model complexity. No automatic v2.6.15 stage is
authorized.

## Cross-repository characterization handoff

The data repository consumes schema `1.0` characterization bundles from the
independently installable `materials-characterization-analyzer` repository.

The handoff validates:

- explicit `sample_id` rather than row order;
- bundle paths, sizes, hashes, and exact feature columns;
- finite numeric values and semantic feature identity;
- source and preprocessing provenance;
- sample-context and external process-table identity fields;
- one-to-one process-characterization integration;
- deterministic reports and manifests.

Pinned public workflows cover DWCNT, RWGS XRD/EDS, four carbon material classes,
and NIST AM-Bench 2018-02 optical metrology. Blocked SEM quantification,
unresolved Ni context, distinct material-class comparisons, and source-reported
microscopy limitations remain explicitly preserved.

These workflows validate software contracts and evidence lineage. They do not
prove phase identity, chemical state, identical aliquots, mechanism, causality,
prediction, optimization, or engineering-release suitability.

## Representative NIST AM-Bench workflow

The representative workflow performs:

```text
verified source-table case
-> sample-ID and provenance integration
-> artifact-integrity closeout
-> process-design identifiability audit
-> bounded minimum next-experiment plan
-> Diagnostic scientific closeout
```

The evidence contains one material, one machine, 10 explicit tracks, and three
coupled power-speed conditions. It covers 3 of 6 combinations in the observed
2 x 3 grid.

The current decision remains
`not_ready_for_predictive_or_causal_modeling`. Interaction and curvature are not
identified by the existing design. The immediate bounded recommendation is to
add the three missing factorial combinations with at least three traces per
condition. No response model is trained and no process optimum is generated.

## Compatibility

output schemas, source tables, and local-only artifact policies. The two

## Security and artifact policy

The release does not intentionally include credentials, private datasets, raw
archives lacking redistribution approval, generated `outputs/`, user-specific
absolute paths, arbitrary serialized Python objects, or local row-level
prediction artifacts.

External datasets, publications, standards, and software retain their own
licenses and citation requirements. The repository MIT license does not
relicense them.

## Validation boundary

Release validation covers software behavior, deterministic artifacts, metadata
consistency, checksum-bound evidence, and tracked cross-repository compatibility.
It does not establish instrument calibration, measurement uncertainty, sample
comparability, causal validity, mechanism validity, predictive generalization,
or production engineering readiness.

## Explicit nonclaims

v2.6.0 does not claim successful Battery forecasting, zero-shot generalization,
SOH or RUL prediction, degradation-mechanism identification, independent
external validation, automatic phase or chemical-state identification, causal
laser-power or scan-speed effects, process optimization, cross-machine or
cross-material generalization, autonomous engineering decisions, or production
